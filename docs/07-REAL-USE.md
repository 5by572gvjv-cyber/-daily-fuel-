# 07 真实使用验证（一周）

目标：把「看起来能用」变成「每天愿意用」。只验三件事——

1. 记录耗时是否达到 PRD 的验收目标：常用食物约 5 秒、普通自制餐约 15 秒、复杂外卖约 60 秒；
2. 哪些操作会出错、需要重来，或让人犹豫；
3. 有没有 P0 阻断（数据丢失、算错、写了改不了、撤销重复累计）。

本周**不加新功能**。发现的问题只记录，第 8 天统一排期。

## 每天的最小动作

- 早餐、午餐、晚餐各记一次（只记主菜也算）；
- 至少一次用「常用」一键记录；
- 至少一次点铅笔改重量，确认营养值跟着变；
- 至少一次删除后点「撤销」，确认没有重复累计；
- 周末做一次「设置 → 导出备份」。

## P0 判定（出现任意一条，当天停止其他事，先修）

- 记录的数值与实际不符，或改了重量汇总没变；
- 数据丢失：刷新、切页、关掉重开后记录消失；
- 写了改不了，只能删除重记；
- 撤销后重复累计，或删除后仍计入总量；
- 备份恢复后数据错乱，或恢复后打不开。

P1 / P2 写进表格最后一列，不打断当天使用。

## 本周重点观察的已知摩擦点（先别改，看它到底有多烦）

1. **常用食物一律记到「加餐」**：如果你每天都要点铅笔改成午餐/晚餐，说明默认值错了，这个改动优先级很高。
2. **顶部「界面状态」按钮是调试用的**：误触会让整页变成加载/空/错误状态，再点一次才回来。真用时它是否碍事，需要你判断。
3. **图片识别入口是禁用占位**，点不动是预期，不是 bug。
4. **撤销只在 toast 出现时有效**，几秒后消失就只能去餐食里手动删。
5. **一餐有多条记录时**，改其中一条不会自动调整同餐其它条目，需要逐条改。

## 第 8 天复盘

把这 7 行表格 + 导出的 `daily-fuel-backup-*.json` 给 AI，可以算出：

- 有记录的天数、总条目数、平均每餐条目数（判断是真的在用，还是只在验收那天用了）；
- 三次计时的中位数与验收目标的差距；
- P0 清单与修复顺序，P1 折进 08 阶段。

## 当前基线（07.1 修完后的实测状态）

| 操作 | 交互步数 | 说明 |
| --- | --- | --- |
| 常用食物一键记录 | 1 次点击 | 点「常用」条目即写入，该餐次自动展开，toast 说明记到哪一餐并可撤销 |
| 修改一条记录的重量 | 铅笔 → 改数字 → 保存，3 步 | 按记录内的每克营养值重算，反复修改不累计误差；可同时改餐次 |
| 同餐次内改餐 | 铅笔 → 换「记到哪一餐」→ 保存 | 原餐次若无其它条目会一起移除 |
| 自然语言解析 | 输入 → 解析并确认 → 确认并保存，3 步 | 入口就在今日页输入框；只匹配本机食物与明确重量，不调用 AI |

超过 3 步才能完成一次记录，就算摩擦点，记下来。记录入口只有今日页一个（原独立记录页已合并进来），如果一周里你还在找「记录」那个入口，记下来。
